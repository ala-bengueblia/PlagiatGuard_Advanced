3. COMMENT LE SYSTÈME DÉTECTE LES SIMILITUDES

PlagiatGuard combine plusieurs axes complémentaires. Les scores des méthodes
différentes ne doivent pas être additionnés ni présentés comme un seul
pourcentage global de plagiat.

AXE A — SIMILARITÉ TEXTUELLE
Le détecteur classique analyse le texte extrait et calcule des indicateurs de
ressemblance. Le rapport peut contenir :
- max_similarity ;
- citation_overlap_ratio ;
- adjusted_similarity ;
- threshold ;
- flagged.

Le seuil par défaut observé dans l'API est 0.55. Un résultat qui dépasse un
seuil indique un cas à examiner, mais ne prouve pas automatiquement un plagiat.

AXE B — SIMILARITÉ SÉMANTIQUE : SENTENCE TRANSFORMERS + FAISS

Modèle utilisé :
    sentence-transformers/all-MiniLM-L6-v2

A. Préparation du corpus :
1. Les documents de référence sont placés dans data/corpus.
2. Le texte est extrait des fichiers.
3. Les textes sont découpés en passages (segmentation).
4. Sentence Transformers transforme chaque passage en vecteur numérique,
   appelé embedding.
5. Les vecteurs sont enregistrés dans un index FAISS.
6. Les métadonnées (nom et chemin de la source) sont conservées pour retrouver
   le document d'origine.

B. Analyse d'un nouveau document :
1. Le texte du document soumis est extrait.
2. Il est découpé en passages.
3. Le même modèle transforme ces passages en embeddings.
4. FAISS recherche les vecteurs les plus proches dans l'index.
5. Le pipeline récupère les passages et leurs métadonnées.
6. Les correspondances, scores et sources sont présentés dans le rapport.

Rôle des composants :
- Sentence Transformers : transforme le texte en vecteurs sémantiques.
- Embedding : représentation numérique d'un passage.
- Similarité cosinus : mesure la proximité entre deux vecteurs.
- FAISS : recherche efficacement les vecteurs les plus proches.
- Métadonnées : permettent de retrouver le fichier source.

Formule de similarité cosinus :
    cos(A,B) = (A . B) / (||A|| x ||B||)

Une valeur plus élevée indique une proximité vectorielle plus importante.
Les scores ne sont pas des pourcentages de plagiat et il n'existe pas de seuil
universel permettant de conclure automatiquement au plagiat.

Paramètres du pipeline connus :
    top_k=5
    local_threshold=0.25

top_k=5 demande jusqu'à cinq correspondances candidates par passage.
local_threshold est un paramètre du pipeline local ; il ne faut pas le
confondre avec le seuil 0.55 du détecteur classique.

Fichiers générés :
    artifacts/research_index/passages.faiss
    artifacts/research_index/passages.json

passages.faiss contient l'index vectoriel. passages.json conserve les passages
et leurs métadonnées.

AXE C — CITATIONS ET RECHERCHE WEB
Le pipeline analyse les citations et références. Une recherche Web est
disponible en option, mais elle est désactivée par défaut (enable_web=False)
dans le pipeline connu. Ne pas présenter la recherche Web comme active pour
chaque analyse.

LIMITES :
- Une similarité élevée n'est pas une preuve automatique de plagiat.
- Une similarité faible ne garantit pas l'absence de plagiat.
- La qualité dépend du corpus, de l'extraction et du modèle.
- Une vérification humaine reste indispensable.

4. AJOUTER LES DOCUMENTS DE RÉFÉRENCE

Placer les fichiers dans :
    data\corpus

Formats gérés par le script d'indexation connu :
    .txt
    .pdf
    .docx
    .odt

Exemple :
    data\corpus\document1.txt
    data\corpus\document2.pdf
    data\corpus\document3.docx

Vérifier les fichiers :
    Get-ChildItem .\data\corpus -Recurse -File

Utiliser des documents lisibles et pertinents, et conserver les originaux.

5. CONSTRUIRE OU RECONSTRUIRE L'INDEX FAISS

Depuis la racine du projet, avec .venv activé et PYTHONPATH défini :
    python scripts/build_faiss_index.py

Le script recherche les documents du corpus, extrait le texte, segmente les
contenus, calcule les embeddings et construit l'index FAISS.

Vérifier les fichiers produits :
    Get-ChildItem .\artifacts\research_index

Fichiers attendus :
    passages.faiss
    passages.json

Reconstruire l'index après ajout ou modification des documents du corpus.
Il n'est pas nécessaire de le reconstruire à chaque analyse.

8. AUTHENTIFICATION JWT

Pour générer un token pour un compte existant :
    python scripts/create_token.py --username admin

Saisir le mot de passe lorsque le programme le demande.
Ne jamais publier ni partager le token JWT. Si un token a été exposé, le
considérer comme compromis et renouveler les identifiants/configurations
de sécurité concernés.

Dans Swagger, l'en-tête d'autorisation est de la forme :
    Bearer VOTRE_TOKEN

Remplacer VOTRE_TOKEN par le token obtenu.

9. LANCER L'API FASTAPI

Dans un premier terminal :

    .\.venv\Scripts\Activate.ps1

Adresses :

    http://127.0.0.1:8000/docs
    http://127.0.0.1:8000/health

Endpoints connus :
    GET  /health
    POST /analyze/text
    POST /analyze/file
    POST /admin/reload-index

Tester /health dans le navigateur :
    http://127.0.0.1:8000/health

Tester /analyze/text dans Swagger :
1. Ouvrir http://127.0.0.1:8000/docs.
2. Cliquer sur Authorize.
3. Entrer Bearer suivi du token.
4. Ouvrir POST /analyze/text puis Try it out.
5. Utiliser ce corps JSON :

    {
      "text": "Artificial intelligence allows machines to learn from data. Machine learning uses algorithms to identify patterns.",
      "threshold": 0.55
    }

6. Cliquer sur Execute et examiner la réponse.

Examiner séparément les résultats classiques et advanced_research, notamment
local_matches et citation_analysis. Les scores classiques et FAISS mesurent
des choses différentes.

Tester /analyze/file :
1. Ouvrir POST /analyze/file.
2. Cliquer sur Try it out.
3. Sélectionner un fichier TXT, PDF, DOCX ou ODT.
4. Exécuter et examiner le rapport.

POST /admin/reload-index est réservé à l'administrateur. Utiliser cette route
seulement si la version de api.py installée implémente le rechargement.
Une réponse 501 signifie que cette fonctionnalité n'est pas disponible dans
la version courante de la route ; ce n'est pas nécessairement une panne FAISS.

15. CONCLUSION

PlagiatGuard Advanced combine une analyse textuelle classique, une recherche
sémantique et une analyse des citations. Sentence Transformers transforme les
passages en embeddings. FAISS recherche les vecteurs les plus proches dans le
corpus. Le pipeline rassemble les correspondances et leurs sources.

Le système aide à identifier les ressemblances ; il ne prononce pas
automatiquement un jugement définitif de plagiat. L'interprétation doit tenir
compte du contexte, des citations, des références et d'une vérification humaine.
